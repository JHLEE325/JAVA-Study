## Annotation

## 1. Annotation 정의하는 방법

### Annotation이란?
- 코드에 메타데이터(metadata)를 추가하는 문법
- 실행 로직이 아니라 컴파일러 / JVM / 프레임워크가 해석하는 정보
- 대표 예시 : `@Override`, `@Deprecated`, `@SuppressWarnings`

### 기본 정의 방법
```java
public @interface MyAnnotation {
}
```
- `@interface` 키워드로 정의
- 내부는 메서드 형태로 속성 정의

### Annotation 요소 정의
```java
public @interface MyAnnotation {
    String value();          // 필수값
    int count() default 1;   // 기본값
}
```
특징
- 필드가 아니라 메서드 형태
- 반환 타입만 존재 (파라미터 없음)
- 허용 타입 제한 있음 - primitive, String, enum, annotation, Class

### 사용 방법
```java
@MyAnnotation(value = "test", count = 3)
public class TestClass {
}

// value 단축 문법 (value 하나만 있을 때 생략 가능)
@MyAnnotation("test");
```

### 메타 애노테이션 (애노테이션에 붙는 애노테이션
- `@Retention`
- `@Target`
- `@Documented`
- `@Inherited`

### 내부 동작 관점
컴파일 과정에서 애노테이션은 아래 단계에 개입함
- 컴파일러
- Annotation Processor
- 클래스 파일 metadata로 저장
- 런타임에 Reflection으로 조회 가능

---

## 2. @Retention
`@Retention`은 애노테이션이 언제까지 유지될지를 결정하는 메타 애노테이션

### 정의 위치
```java
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;

@Retention(RetentionPolicy.RUNTIME)
public @interface MyAnnotation {
}
```

#### RetentionPolicy 종류
#### SOURCE
```java
@Retention(RetentionPolicy.SOURCE)
```
- 컴파일 전에 사라짐
- `.class 파일에 포함되지 않음`

사용 예시
- `@Override`
- `@SupressWarnings`

특징
- 컴파일러용
- 런타임에서 볼 수 없음

#### CLASS (기본값)
```java
@Retention(RetentionPolicy.CLASS)
```
- `.class 파일까지는 포함`
- JVM 런타임에서는 접근 불가

특징
- 바이트코드에는 존재
- Reflection으로 읽을 수 없음

#### RUNTIME
```java
@Retention(RetentionPolicy.RUNTIME)
```
- `.class 포함 + 런타임까지 유지`
- Reflection으로 조회 가능

사용 예시
- Spring
- JPA
- 대부분의 프레임워크

#### 각 부분별 비교
| 정책      | 컴파일 | 클래스 파일 | 런타임 | 사용 목적    |
| ------- | --- | ------ | --- | -------- |
| SOURCE  | O   | X      | X   | 컴파일 체크   |
| CLASS   | O   | O      | X   | 바이트코드 분석 |
| RUNTIME | O   | O      | O   | 런타임 처리   |


### 내부 동작 관점
컴파일 과정에서
- SOURCE → 컴파일러 단계에서만 사용 후 제거
- CLASS → `.class`에 metadata로 저장
- RUNTIME → JVM 메모리까지 유지
Retention은 Annotation Processing / Reflection 가능 여부를 결정하는 핵심 옵션

## 3. @Target
`@Target`은 애노테이션을 적용할 수 있는 위치를 제한하는 메타 애노테이션

### 정의 방법
```java
import java.lang.annotation.Target;
import java.lang.annotation.ElementType;

@Target(ElementType.METHOD)
public @interface MyAnnotation {
}
```

### ElementType 종류
#### TYPE
```java
@Target(ElementType.TYPE)
// 클래스, 인터페이스, enum

@MyAnnotation
class Test {}
```

#### FIELD
```java
@Target(ElementType.FIELD)
// 필드(멤버 변수)

class Test {
    @MyAnnotation
    private String name;
}
```

#### METHOD
```java
@Target(ElementType.METHOD)

@MyAnnotation
public void run() {}
```

#### PARAMETER
```java
@Target(ElementType.PARAMETER)

public void run(@MyAnnotation String name) {}
```

#### CONSTRUCTOR
```java
@Target(ElementType.CONSTRUCTOR)
```

#### LOCAL_VARIABLE
```java
@Target(ElementType.LOCAL_VARIABLE)
```

#### ANNOTATION_TYPE
```java
@Target(ElementType.ANNOTATION_TYPE)
// 애노테이션 위에 붙는 애노테이션 정의용
```

#### PACKAGE
```java
@Target(ElementType.PACKAGE)
```

#### TYPE_PARAMETER (Java 8)
```java
class Test<@MyAnnotation T> {}
// 제네릭 타입 선언
```

#### TYPE_USE (Java 8)
```java
List<@MyAnnotation String> list;
// 타입이 사용되는 모든 위치
```

### @Target이 없는 경우에는 어떻게 될까
모든 위치에 사용이 가능하다
```java
public @interface MyAnnotation {}
```
- 제한이 없어서 아무데나 붙일 수 있음
- 실무에선느 항상 target을 명시하는 편

### @Target이 필요한 이유
#### 컴파일 타임 안전성 확보
```java
@Target(ElementType.METHOD)

@MyAnnotation
int x; // 컴파일 에러
```
잘못된 위치 사용 방지

#### 의미 명확화
- @Controller → 클래스
- @Bean → 메서드
- @Autowired → 필드/생성자
- 설계 의도를 강제

### 핵심 애노테이션
| 애노테이션         | Target                       |
| ------------- | ---------------------------- |
| @Override     | METHOD                       |
| @Entity       | TYPE                         |
| @Autowired    | FIELD / CONSTRUCTOR / METHOD |
| @RequestParam | PARAMETER                    |

## 4. @Documented
`@Documented`는 해당 애노테이션이 JavaDoc 문서에 포함될지 여부를 결정하는 메타 애노테이션 <br>
해당 애노테이션을 API 문서에 노출할지를 결정

### 정의 방법
```java
import java.lang.annotation.Documented;

@Documented
public @interface MyAnnotation {
}
```

### 동작 방식
`@Documented`가 붙은 애노테이션은 JavaDoc 생성 시 문서에 포함됨

### 사용 예시
```java
public @interface MyAnnotation {}

@MyAnnotation
public class Test {}

// JavaDoc에 @MyAnnotation이 표시되지 않음

@Documented
public @interface MyAnnotation {}

// JavaDoc에 @MyAnnotation이 표시됨
```

### @Documented가 필요한 이유
#### API 사용자에게 정보 제공
- 라이브러리 사용자 입장에서 어떤 애노테이션이 중요한 지 알 수 있음
- 이 애노테이션은 공개 API의 일부라는 정보를 얻을 수 있음

#### 문서 기반 개발 지원
- JavaDoc 기반 문서화 시
- 애노테이션도 API 스펙으로 포함

### 예시 및 주로 사용하는 경우
```java
@Documented
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface Override {}

// @Override는 문서에도 노출됨
```

실무 사용 예시
| 상황          | @Documented 필요 여부 |
| ----------- | ----------------- |
| 라이브러리/프레임워크 | ✅ 사용              |
| 내부용 애노테이션   | ❌ 보통 생략           |

### @Documented에 대한 오해
런타임과는 관계가 없이 문서용이기 때문에 실행, Reflection과 무관 <br>
핵심
- 실행 → `@Retention`
- 위치 → `@Target`
- 문서 → `@Documented`

## 5. Annotation Processor (애노테이션 프로세서)
애노테이션 프로세서는 컴파일 타임에 애노테이션을 처리해서 코드를 생성하거나 검증하는 도구 <br>
컴파일 시점에 애노테이션을 읽고 작업을 하는 것

### 애노테이션 프로세서 실행 시점
자바 컴파일 과정:
1. 소스 코드 작성
2. 컴파일러 실행 (javac)
3. **애노테이션 프로세싱 단계**
4. 바이트코드 생성
컴파일 과정 중간에 개입

### 애노테이션 프로세서 필요 이유
#### 반복 코드 제거 (코드 생성)
- Getter / Setter 자동 생성
- Builder 패턴 생성
- Mapper 코드 생성

대표:
- Lombok
- MapStruct

#### 컴파일 타입 검증
- 잘못된 애노테이션 사용 체크
- 규칙 위반 시 컴파일 에러 발생
- 런타임 에러 -> 컴파일 에러로 앞당겨서 사전에 처리 가능하게 함

### 동작 방식
1. 애노테이션 탐색
2. 해당 애노테이션 처리
3. 코드 생성 / 검증 수행

### 기본 구현 구조
```java
@SupportedAnnotationTypes("com.example.MyAnnotation")
@SupportedSourceVersion(SourceVersion.RELEASE_8)
public class MyProcessor extends AbstractProcessor {

    @Override
    public boolean process(Set<? extends TypeElement> annotations, RoundEnvironment roundEnv) {
        // 애노테이션 처리 로직
        return true;
    }
}
```

### 핵심 API
AbstractProcessor
- 애노테이션 프로세서의 기본 클래스
RoundEnvironment
- 현재 라운드에서 처리할 애노테이션 정보 제공
Filer
- 파일 생성 (코드 생성 핵심)

### 대표적인 사용 예시
#### Lombok
```java
@Getter
@Setter
class User {
    private String name;
}

// 컴파일 시 getter/setter 자동 생성
```

#### MapStruct
```java
@Mapper
interface UserMapper {
    UserDto toDto(User user);
}

// 구현 클래스 자동 생성
```

### Annotation Processor vs Reflection
| 구분    | Annotation Processor | Reflection |
| ----- | -------------------- | ---------- |
| 시점    | 컴파일 타임               | 런타임        |
| 성능    | 매우 빠름                | 상대적으로 느림   |
| 안정성   | 컴파일 에러               | 런타임 에러     |
| 코드 생성 | 가능                   | 불가능        |
