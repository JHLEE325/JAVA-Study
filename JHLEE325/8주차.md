## Interface (인터페이스)

## 1. 인터페이스 정의하는 방법

### 인터페이스(Class)의 개념
- 인터페이스는 객체의 "행위(기능)"만 정의한 추상 타입
- 클래스와 달리 구현 없이 메서드 시그니처만 정의
- 다형성, 설계 분리(추상화)를 위한 핵심 도구

### 인터페이스의 특징
- `interface` 키워드 사용
- 모든 메서드는 기본적으로 `public abstract`
- 필드는 `public static final` (상수)

### 인터페이스 vs 클래스
| 구분    | 인터페이스       | 클래스   |
| ----- | ----------- | ----- |
| 키워드   | interface   | class |
| 메서드   | 추상 메서드 (기본) | 구현 가능 |
| 필드    | 상수만 가능      | 변수 가능 |
| 생성자   | 없음          | 있음    |
| 다중 상속 | 가능          | 불가능   |

### 인터페이스의 목적
#### 1. 추상화
- 무엇을 할 수 있는가 정의
- 어떻게 하는가 <- 이거는 구현체에서

#### 2. 결합도 감소
- 구현 변경 -> 인터페이스는 그대로 있어도 됨
- 유지보수성 상승

#### 3. 다형성 기반 설계
```java
Animal a = new Dog();
Animal a2 = new Cat();
```

## 2. 인터페이스 구현하는 방법

### 인터페이스 기본 문법
- 인터페이스는 구현이 없기 때문에 객체 생성 불가
- 반드시 클래스가 implements 키워드로 구현

기본 문법
```
interface Animal {
    void sound();
}

class Dog implements Animal {
    @Override
    public void sound() {
        System.out.println("멍멍");
    }
}
```

### 핵심 규칙
#### 1. 반드시 모든 메서드를 구현해야함
```java
interface A {
    void a();
    void b();
}

class B implements A {
    public void a() {} // OK
    // b() 미구현 → 컴파일 에러
}
```

#### 2. 접근제어자 주의
```java
interface A {
    void method();
}

class B implements A {
    void method() {} // 컴파일 에러
    public void methid() {} // 올바른 코드
}
```
이유
- 인터페이스 메서드는 `public` 일 때 구현 시 더 좁은 접근제어자 사용 불가능

#### 3. 다중 인터페이스 구현 가능
```java
interface Flyable {
    void fly();
}

interface Swimmable {
    void swim();
}

class Duck implements Flyable, Swimmable {
    public void fly() {}
    public void swim() {}
}
```
자바에서 다중 상속은 인터페이스로 해결

#### 4. 추상 클래스와 함께 사용 가능
```java
abstract class Animal {
    abstract void eat();
}

interface Flyable {
    void fly();
}

class Bird extends Animal implements Flyable {
    void eat() {}
    public void fly() {}
}
```
클래스 상속 + 인터페이스 구현 동시에 사용 가능

### 구현 시 내부 동작
- 인터페이스는 레퍼런스 타입
- 실제 객체는 Heap에 생성되고, 인터페이스 타입은 참조 역할

## 3. 인터페이스 레퍼런스를 통해 구현체를 사용하는 방법

### 핵심개념
인터페이스 타입으로 객체를 다룬다
```java
interface Animal {
    void sound();
}

class Dog implements Animal {
    public void sound() {
        System.out.println("멍멍");
    }
}

class Cat implements Animal {
    public void sound() {
        System.out.println("야옹");
    }
}
```
```java
Animal a = new Dog();
Animal b = new Cat();

a.sound();
b.sound();
```
#### 핵심 동작 원리
1. 컴파일 시점
   - 변수 타입 기준 -> `Animal`
   - Animal에 정의된 메서드만 호출 가능
2. 런타임 시점
   - 실제 객체 기준 -> `Dog`, `Cat`
   - 해당 클래스의 메서드 실행
동적 바인딩

#### 사용 이유
1. 구현체 교체 가능
   ```java
   Animal a = new Dog();
   // → new Cat()으로 바꿔도 코드 영향 없음
   ```
2. 결함도 감소
   - 코드가 구현이 아니라 인터페이스에 의존
   - 유지보수, 확장성 증가
3. 다형성
   ```java
   List<Animal> animals = List.of(new Dog(), new Cat());
   
   for (Animal a : animals) {
       a.sound();
   }
   ```
   - 같은 코드로 다양한 객체 처리 가능

## 4. 인터페이스 상속
인터페이스는 인터페이스끼리 `extends`키워드를 사용하여 상속이 가능하다 <br>
그리고 다중상속도 가능하다

### 기본 문법
```java
interface Animal {
    void eat();
}

interface Flyable {
    void fly();
}

interface Bird extends Animal, Flyable {
    void sing();
}
```
이 경우에 `Bird`는 `eat()`, `fly()`, `sing()` 을 모두 포함한다
```java
class Sparrow implements Bird {
    public void eat() {}
    public void fly() {}
    public void sing() {}
}
// 위처럼 부모의 인터페이스까지 전부 구현해야 함
```

### 핵심 특징
1. 다중 상속 가능
   ```java
   interface A {}
   interface B {}
   
   interface C extends A, B {}
   ```
   - 클래스와의 가장 큰 차이
2. 이론적으로 메서드 충돌이 없음
   - 인터페이스는 기본적으로 구현이 없기 때문에 다중 상속 시 충돌 문제 없음
3. 계층적 설계 가능
   ```java
   interface Vehicle {
       void move();
   }
     
   interface Car extends Vehicle {
      void drive();
   }
   ```

### Java 8 이후의 중요 포인트
default 메서드 충돌 발생 가능
```java
interface A {
    default void hello() {
        System.out.println("A");
    }
}

interface B {
    default void hello() {
        System.out.println("B");
    }
}

class C implements A, B {
    // 반드시 override 해야 함
    public void hello() {
        A.super.hello(); // 또는 B.super
    }
}
```
default는 구현이 있기 때문에 충돌 발생 가능

### 인터페이스 vs 클래스 상속 차이
| 구분     | 인터페이스   | 클래스     |
| ------ | ------- | ------- |
| 키워드    | extends | extends |
| 다중 상속  | 가능      | 불가능     |
| 구현     | 없음 (기본) | 있음      |
| 충돌 가능성 | 낮음      | 높음      |

## 5. 인터페이스의 기본 메소드 (Default Method, Java8)

### Default Method의 개념
- Java8에서 도입
- 인터페이스에 구현을 가진 메서드 추가 기능
  ```java
  interface Animal {
    default void move() {
        System.out.println("이동한다");
    }
  }
  ```
### 등장 이유
기존 인터페이스에 메서드를 추가할 때 모든 구현 클래스 전부 컴파일 에러 발생 <br>
이를 해결하기 위해 default method가 있음

### 기본 사용법
```java
interface Animal {
    default void sound() {
        System.out.println("동물 소리");
    }
}

class Dog implements Animal {}

Dog d = new Dog();
d.sound(); // "동물 소리"

// 오버라이딩 가능
class Dog implements Animal {
    @Override
    public void sound() {
        System.out.println("멍멍");
    }
}
```

### default method의 장점과 단점
#### 장점
- 인터페이스 확장 가능
- 기존 코드에 영향일 끼치지 않음
- 공통 로직을 일부 제공할 수 있음

#### 단점
- 인터페이스가 "순수 추상"이 아니게 됨
- 책임이 애매해짐
- 남용 시 설계가 깨짐

#### 언제 써야 하는가?
- 기존 인터페이스의 기능을 확장하고 싶을 때
- 인터페이스에 간단한 공통 로직을 제공하고 싶을 때
- Collection, Stream API 등

## 6. 인터페이스의 static 메소드 (Java 8)
Java 8부터 인터페이스에 static 메서드를 정의 가능하다 <br>
클래스터럼 직접 호출하는 메서드 <br>

예시
```java
interface Animal {
    static void info() {
        System.out.println("동물 인터페이스");
    }
}

// 호출 방법
Animal.info();
// 인터페이스 이름으로만 호출 가능
```

### 특징
1. 구현 클래스에서 상속되지 않음
   ```java
   class Dog implements Animal {}

   Dog.info(); // 컴파일 에러 static method는 상속 안됨
   ```
2. 오버라이딩 불가능
   ```java
   class Dog implements Animal {
     static void info() {} // 별개의 메서드
   }
   ```
3. 인터페이스 내부 유틸 메서드 역할
   ```java
   interface MathUtil {
     static int add(int a, int b) {
        return a + b;
       }
   }
   ```

### default vs static
| 구분    | default  | static |
| ----- | -------- | ------ |
| 호출 방식 | 객체       | 인터페이스  |
| 오버라이딩 | 가능       | 불가능    |
| 상속 여부 | O        | X      |
| 목적    | 기본 구현 제공 | 유틸성    |

### 필요한 이유
인터페이스 내부에 관련된 기능알 같이 묶기 위해서
- `Comparator.comparing()`
- `Stream.of()`
- 인터페이스 + 유틸 함수 결합

### static method의 장점과 단점
#### 장점
- 관련 로직의 응집도가 증가
- 별도 유틸 클래스 필요 없이 유틸 함수를 사용 가능

#### 단점
- 과도하면 인터페이스 책임이 증가됨

## 7. 인터페이스의 private 메소드 (Java 9)
Java 9부터 인터페이스에 private 메서드 정의 가능 <br>
인터페이스 내부에서만 사용하는 헬퍼 메서드
```java
interface Animal {
    default void sound() {
        printMessage();
    }

    private void printMessage() {
        System.out.println("동물 소리");
    }
}
```

### private 메서드의 등장 이유
default / static 메서드 중복 코드 제거
```java
interface A {
    default void a() {
        System.out.println("공통 로직");
    }

    default void b() {
        System.out.println("공통 로직"); // 중복
    }
}
```
위 문제를 아래처럼 해결
```java
interface A {
    default void a() {
        common();
    }

    default void b() {
        common();
    }

    private void common() {
        System.out.println("공통 로직");
    }
}
```

### private 메서드 특징
1. 외부 접근 불가
   ```java
   A a = new A(); // 인터페이스 생성 불가
   a.common();    // 접근 불가
   ```
2. 구현 클래스에서도 접근 불가
   ```java
    class B implements A {
       void test() {
        common(); // 컴파일 에러
       }
   }
   ```
3. default / static 에서만 사용 가능
   ```java
   interface A {
       default void a() {
           helper();
       }
   
       static void b() {
           // helper(); (instance private 호출 불가)
       }
   
       private void helper() {}
   }
   ```

### private 메서드 정리 및 장단점
| 메서드 타입         | 접근 가능 범위            |
| -------------- | ------------------- |
| private        | 인터페이스 내부            |
| private static | 인터페이스 내부(static 포함) |

#### 장점
- 코드 중복 제거
- 가독성 향상
- 내부 로직 캡슐화

#### 단점
- 인터페이스 복잡도 증가
- 과도한 로직 집중 위험
