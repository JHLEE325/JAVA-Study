## Class (클래스)

## 1. 클래스 정의하는 방법

### 클래스(Class)의 개념
클래스는 객체를 생성하기 위한 설계도 <br>

객체지향 프로그래밍에서 클래스는
- 객체의 상태(state) -> 필드(field)
- 객체의 행동(behavior) -> 메서드(method)
데이터 + 동작을 하나로 묶는 단위 <br>

예시
```java
class Person {
    String name;
    int age;

    void introduce() {
        System.out.println("Hello");
    }
}
```

| 개념       | 의미                   |
| -------- | -------------------- |
| Class    | 객체를 만들기 위한 설계도       |
| Object   | 클래스 기반으로 생성된 실제 인스턴스 |
| Instance | 메모리에 생성된 객체          |

<br>

### 클래스(Class) 구성 요소

자바 클래스는 일반적으로 다음 요소들로 구성됨
```
class Car {

    String model;   // 필드
    int speed;      // 필드

    Car(String model) {   // 생성자
        this.model = model;
    }

    void accelerate() {   // 메서드
        speed += 10;
    }
}
```

<br>

### 클래스(Class) 선언 문법

기본문법
```
접근제어자 class 클래스이름 {

}
```
예시
```java
public class Person {

}
```
설명
| 요소     | 설명         |
| ------ | ---------- |
| public | 접근 제어자     |
| class  | 클래스 선언 키워드 |
| Person | 클래스 이름     |

#### 네이밍 규칙
자바 클래스는 파스칼케이스 사용
| 규칙         | 설명       |
| ---------- | -------- |
| PascalCase | 첫 글자 대문자 |
| 명사 사용      | 객체를 표현   |
| 의미 있는 이름   | 역할 명확    |

<br>

### 클래스(Class)와 파일
클래스의 파일에는 규칙이 있다. <br>
```
public class 이름 = 파일 이름

예시
Person.java
```
```java
public class Person{
}
```

#### 하나의 파일에 여러 클래스 정의
public 클래스는 하나만 가능하나 여러 클래스 정의 가능
```java
public class Main {

}

class A {

}

class B {

}
```

<br>

### 클래스 메모리 관점
클래스는 JVM에서 다음 과정으로 로딩됨
1. ClassLoader가 클래스 로딩
2. Method Area에 클래스 정보 저장
3. 객체 생성 시 Heap에 인스턴스 생성

JVM 구조
```
Method Area
   │
   │  Class metadata
   │
Heap
   │
   │  Object Instance
   │
Stack
   │
   │  Reference variable
```
메모리 구조
```
Stack
 └ p ---------

Heap
 └ Person 객체

Method Area
 └ Person class metadata
```

<br>

### 클래스와 객체의 차이
| 구분 | 클래스    | 객체           |
| -- | ------ | ------------ |
| 개념 | 설계도    | 실제 데이터       |
| 존재 | 코드     | 메모리          |
| 생성 | 컴파일    | 런타임          |
| 예  | Person | new Person() |
```java
Class : Person
Object : p1, p2, p3
```

<br>

### 클래스 설계 원칙
1. 단일 책임 원칙 (SRP) : 클래스는 하나의 책임만 가져야 한다
2. 캡슐화 : 데이터는 보호하고 메서드를 통해 접근한다
3. 응집도 : 클래스 내부 기능은 서로 관련된 기능이어야 한다

## 2. 객체 만드는 방법 (new 키워드 이해)

### 객체(Object)란 무엇인가
객체는 클래래스를 기반으로 생성된 실제 인스턴스 <br>
클래스가 설계도라면 객체는 설계도로 만들어진 실제 제품 <br>
개념
```
Class (설계도)
      │
      │ new
      ▼
Object (실제 인스턴스)
```

<br>

### 객체 생성 문법
기본 문법
```java
// 클래스이름 변수 = new 클래스이름();

Person p = new Person();
```
구성
| 요소       | 의미     |
| -------- | ------ |
| Person   | 클래스 타입 |
| p        | 참조 변수  |
| new      | 객체 생성  |
| Person() | 생성자    |

### 객체 생성 과정 (JVM 내부 동작)
```java
Person p = new Person();
```
위 코드를 실행했을 때 JVM 내부에서 일어나는 과정
1. 클래스 로딩 : 클래스가 사용되면 ClassLoader가 `.class` 파일을 로딩, 클래스 정보는 Method Area에 저장
2. Heap 메모리에 객체 생성 : Heap에 객체가 생성되고 필드는 기본값으로 초기화
3. 생성자 호출 : 객체 생성 직후 생성자가 실행됨
4. 참조 변수에 주소 저장

#### 객체 생성 비용
1. Heap allocation
2. 생성자 실행
3. GC 관리 대상 추가

객체 대량 생성은 성능에 영향이 있음

#### 객체 생명주기
```
생성
 ↓
사용
 ↓
참조 제거
 ↓
GC
```

#### 객체 생성 방식
자바에서 객체 생성 방법은 여러가지가 있음
1. new
2. Reflection
   ```java
   Class clazz = Person.class;
   Person p = (Person) clazz.newInstance();
   ```
3. clone()
   ```java
   Person p2 = p1.clone();
   ```
4. deserializtion : 객체를 파일에서 복원

<br>

### 객체 메모리 구조
| 영역          | 역할     |
| ----------- | ------ |
| Stack       | 참조 변수  |
| Heap        | 객체     |
| Method Area | 클래스 정보 |

<br>

### 객체는 참조 타입?!
자바의 객체 변수는 객체 자체가 아니라 주소를 저장
```java
Person p1 = new Person();
Person p2 = p1;
```
메모리
```
Stack
 ├ p1 ------
 └ p2 ------

Heap
 └ Person object
```

<br>

### 객체 비교 (== vs equals)
객체 비교 시
- == 주소 비교
- equals() 내용 비교

예시
```java
Person a = new Person();
Person b = new Person();

System.out.println(a == b); // false
```
객체는 Heap에 각각 생성됨

<br>

### new 키워드의 역할
1. Heap 메모리 할당
2. 객체 생성
3. 생성자 호출
4. 객체 주소 반환

## 3. 메소드 정의하는 방법

### 메소드의 개념
메소드는 특정 기능을 수행하는 코드 블록 <br>
객체지향 관점에서 메소드는 객체의 행동(behavior)을 정의
```java
class Calculator {

    int add(int a, int b) { // 메서드
        return a + b;
    }

}
```

<br>

### 메소드 기본 문법
```
접근제어자 반환타입 메소드이름(매개변수) {

    실행 코드

}
```
예시
```java
public int add(int a, int b) {
    return a + b;
}
```
구성 요소
| 요소             | 의미     |
| -------------- | ------ |
| public         | 접근 제어자 |
| int            | 반환 타입  |
| add            | 메소드 이름 |
| (int a, int b) | 매개변수   |
| return         | 반환     |

<br>

### 반환 타입 (Return Type)
메소드는 반환값을 가질 수도 있고 없을 수도 있음 <br>
반환값 있는 경우
```java
int add(int a, int b) {
    return a + b;
}
```
반환값 없는 경우
```java
void printHello() {
    System.out.println("hello");
}
```

<br>

### 메소드 호출
```java
class Calculator {

    int add(int a, int b) {
        return a + b;
    }

}
```
호출
```java
Calculator c = new Calculator();
int result = c.add(3,4);
```
실행 흐름
```
main
  ↓
add()
  ↓
return
```

<br>

### 메소드 호출 시 JVM 동작
메소드 호출 시 JVM Stack Frame이 생성됨
```
JVM Stack

main()
 ├ args
 └ result

add()
 ├ a
 └ b
```
JVM Stack은 메소드 호출 정보를 저장하는 영역

<br>

### 메소드 오버로딩 (Overloading)
같은 이름의 메소드를 여러개 정의할 수 있음<br>
파라미터가 달라야 함<br>
예시
```java
int add(int a, int b) {
    return a + b;
}

double add(double a, double b) {
    return a + b;
}
// 리턴 타입만 다른 경우는 불가능
```

<br>

### static 메소드
static 메소드는 객체 없이 호출 가능
```java
class MathUtil {

    static int add(int a, int b) {
        return a + b;
    }

}

MathUtil.add(1,2);
```
구분
| 구분    | instance method | static method |
| ----- | --------------- | ------------- |
| 객체 필요 | O               | X             |
| 호출    | object.method   | Class.method  |

<br>

### 메소드 설계 원칙
좋은 메소드 특징
1. 단일 책임 : 메소드 하나는 하나의 기능만 수행
2. 짧은 메소드 : 보통 20 ~ 30줄 이하 권장
3. 의미 있는 이름

## 4. 생성자 정의하는 방법 (Constructor)

### 생성자의 개념
생성자는 객체가 생성될 때 자동으로 호출되는 특별한 메소드 <br>
주요 목적
- 객체 초기화
- 필드 값 설정
- 객체 생성 시 필요한 로직 실행

예시
```java
class Person {

    String name;
    int age;

    Person() {
        name = "unknown";
        age = 0;
    }

}

Person p = new Person();
```
실행과정
```
new Person()
   ↓
Heap 객체 생성
   ↓
생성자 실행
   ↓
객체 초기화
```

<br>

### 생성자 특징
생성자는 메소드와 차이가 있음
| 특징    | 설명            |
| ----- | ------------- |
| 이름    | 클래스 이름과 동일    |
| 반환 타입 | 없음            |
| 호출 시점 | 객체 생성 시 자동 호출 |
| 역할    | 객체 초기화        |

#### 생성자 vs 메소드
| 구분    | 생성자     | 메소드    |
| ----- | ------- | ------ |
| 이름    | 클래스 이름  | 자유     |
| 반환 타입 | 없음      | 있음     |
| 호출    | 객체 생성 시 | 명시적 호출 |
| 목적    | 객체 초기화  | 기능 수행  |

#### 기본 생성자
개발자가 생성자를 작성하지 않으면 컴파일러가 자동 생성<br>
생성자를 하나라도 정의하면 기본 생성자는 생성되지 않음

#### 생성자와 필드 초기화
필드 초기화는 생성자 이전에 실행됨
```java
class Example {

    int x = 5;

    Example() {
        x = 10;
    }

}
// 위의 경우 x는 10이 됨
```

<br>

### this() 생성자 호출
생성자 내부에서 다른 생성자를 `this()`를 사용해 호출 가능 <br>
예시
```java
class Person {

    String name;
    int age;

    Person() {
        this("unknown", 0);
    }

    Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

}
```

#### 생성자 체이닝
`this()`를 사용하여 여러 생성자를 연결해 코드 중복을 줄임 <br>
예시
```java
class Person {

    String name;
    int age;

    Person() {
        this("unknown");
    }

    Person(String name) {
        this(name, 0);
    }

    Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

}
```
```
Person()
   ↓
Person(name)
   ↓
Person(name, age)
```

## 5. this 키워드 이해하기

### this의 개념
`this`는 현재 객체(현재 인스턴스)를 가리키는 참조 변수 <br>
즉 메소드나 생성자를 호출한 객체 자신

<br>

### this의 메모리 관점
객체 메소드가 호출되면 JVM은 메소드 호출 시 this 참조를 전달한다. <br>
예시
```java
Person p = new Person();
p.printName();
```
실행 구조
```
Stack
 └ printName()
      └ this → Person 객체

Heap
 └ Person instance
```
메소드 호출 시 JVM Stack에 스택 프레임이 생성되며 해당 메소드가 실행

<br>

### 변수 Shadowing 문제
클래스 필드와 파라미터 이름이 같으면 가려지는(shadowing)이 발생 <br>
예시
```java
class Person {

    String name;

    Person(String name) {
        name = name;
    }

}

// name이 모두 파라미터 name을 가리켜 필드가 초기화 되지 않음
```
해별방법 : this 키워드 사용
```java
class Person {

    String name;

    Person(String name) {
        this.name = name;
    }

}
// this.name은 필드, name은 파라미터
```

<br>

### this 사용이 불가능한 경우
static 메소드는 객체 없이 호출되어 this 사용 불가
```java
class Test {

    static void method() {
        System.out.println(this);
    }

}
// 컴파일 오류 발생
```

<br>

### this vs this()
| 구분     | 의미        |
| ------ | --------- |
| this   | 현재 객체 참조  |
| this() | 다른 생성자 호출 |

예시
```java
this.name = name;
this("Tom", 20);
```
