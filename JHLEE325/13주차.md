## I/O

## 1. 스트림(Stream) / 버퍼(Buffer) / 채널(Channel) 기반의 I/O

### I/O의 기본 개념
자바에서 I/O(Input/Output)는 데이터를 읽고 쓰는 방식을 의미하며 <br>
대표적으로 3가지 추상화 모델이 존재
| 구분      | 핵심 개념    | 특징     |
| ------- | -------- | ------ |
| Stream  | 데이터의 흐름  | 순차적 처리 |
| Buffer  | 임시 저장 공간 | 성능 최적화 |
| Channel | 양방향 통로   | NIO 기반 |

### Stream (스트림 기반 I/O)
#### 개념
- 데이터가 한 방향으로 흐르는 통로
- 입력(InputStream) / 출력(OutputStream)으로 나뉨
#### 특징
- 단방향
- 순차 처리
- blocking 방식
```java
InputStream in = new FileInputStream("test.txt");
int data = in.read();
```
#### 핵심 포인트
- 읽거나 쓰는 작업이 끝날 때까지 스레드가 대기 (Blocking)
- 파일, 네트워크 등 거의 모든 I/O의 기본 모델

### Buffer (버퍼)
#### 개념
- 데이터를 한 번에 처리하기 위해 임시로 저장하는 공간
#### 왜 필요한가??
I/O는 비용이 비싸다 (디스크, 네트워크 측면 등)
- 작은 단위로 계속 읽으면 성능이 저하
- 따라서 모아서 한번에 처리
```java
BufferedInputStream bis = new BufferedInputStream(new FileInputStream("test.txt"));
```
#### 핵심 포인트
- 시스템 호출 횟수 감소
- I/O 성능 향상

### Channel (채널, NIO)
#### 개념
- 데이터를 양방향으로 읽고 쓸 수 있는 통로
- `java.nio` 패키지
```java
FileChannel channel = FileChannel.open(path);
```
#### 특징
- 양방향 (read/write 모두 가능)
- 비동기 / 논블로킹 지원
- Buffer 기반으로 동작

### Stream VS Channel
| 항목 | Stream   | Channel         |
| -- | -------- | --------------- |
| 방향 | 단방향      | 양방향             |
| 방식 | Blocking | Non-blocking 가능 |
| 처리 | 순차       | 병렬/비동기          |
| 사용 | 전통 IO    | NIO             |

## 2. InputStream과 OutputStream

### InputStream과 OutputStream의 개념
#### InputStream
- 데이터를 읽기 위한 추상 클래스
- 바이트 단위 입력

#### OutputStream
- 데이터를 쓰기 위한 추상 클래스
- 바이트 단위 출력

둘 다 `java.io` 패키지의 핵심 기반 클래스

### 각각의 구조
자바의 I/O는 추상 클래스 + 구현 클래스 구조로 되어 있음
```
InputStream
 ├─ FileInputStream
 ├─ ByteArrayInputStream
 ├─ BufferedInputStream

OutputStream
 ├─ FileOutputStream
 ├─ ByteArrayOutputStream
 ├─ BufferedOutputStream
```
핵심 : 확장(Decorator 패턴처럼 조합 가능)

### 주요 메서드
#### InputStream의 주요 메서드
```java
int read()
int read(byte[] b)
int read(byte[] b, int off, int len)
void close()

int data;
while ((data = in.read()) != -1) {
    System.out.print((char) data);
}
```
특징
- 1바이트 읽으면 `int` 반환
- 더이상 데이터가 없으면 `-1`

#### OutputStream의 주요 메서드
```java
void write(int b)
void write(byte[] b)
void write(byte[] b, int off, int len)
void flush()
void close()
```
특징
- write는 버퍼에 쌓일 수 있음
- `flush()`로 쌓인 내용을 강제 출력 가능

### 바이트 단위 처리
| 항목    | 설명            |
| ----- | ------------- |
| 처리 단위 | 1 byte        |
| 대상    | 이미지, 파일, 네트워크 |
| 문자 처리 | 직접 변환 필요      |

### 기본 사용 방법
#### 파일 읽기
```java
InputStream in = new FileInputStream("test.txt");

int data;
while ((data = in.read()) != -1) {
    System.out.print((char) data);
}
in.close();
```

#### 파일 쓰기
```java
OutputStream out = new FileOutputStream("test.txt");

out.write('A');
out.write('B');

out.close();
```

### 성능 이슈 및 해결 방법
1바이트씩 읽는 방법은 비용이 많이 듬 = 느림
```java
BufferedInputStream
BufferedOutputStream
```
버퍼링을 사용하여 한번에 읽을 수 있게 개선

### close()와 flush()의 차이
| 메서드     | 역할          |
| ------- | ----------- |
| close() | 자원 해제       |
| flush() | 버퍼 내용 강제 출력 |

### try-with-resources
```java
try (InputStream in = new FileInputStream("test.txt")) {
    // 사용
}
```
자동 close를 통해 리소스 누수를 방지함

## 3. Byte 스트림 vs Character 스트림

### Byte 스트림과 Character 스트림 개념
#### Byte 스트림
- 바이트(1byte) 단위로 데이터 처리
- 모든 데이터 처리 가능 (이미지, 파일, 네트워크 등)
- 대표 클래스 : InpustStream, OutputStream

#### Character 스트림
- 문자(2byte, char) 단위로 데이터 처리
- 문자 인코딩 자동 처리
- 대표 클래스 : Reader, Writer

### Byte, Character 두 개로 나누는 이유
문자 인코딩 문제가 발생하기 때문
- Byte Stream : 단순 데이터
- Character Stream : 문자 해석 포함
```
byte → (인코딩/디코딩) → char
```

### 핵심 차이점
| 항목  | Byte Stream              | Character Stream |
| --- | ------------------------ | ---------------- |
| 단위  | 1 byte                   | 2 byte (char)    |
| 대상  | 모든 데이터                   | 문자 데이터           |
| 인코딩 | 직접 처리                    | 자동 처리            |
| 클래스 | InputStream/OutputStream | Reader/Writer    |

### 변환 스트림
Byte <-> Character 서로 연결
- InputStreamReader : byte -> character 변환
- OutputStreamWriter : character -> byte 변환

### 언제 무엇을 사용할까??
#### Byte Stream 사용
- 이미지, 영상, 바이너리 파일
- 네트워크 통신
- 파일 복사
> 데이터를 그대로 다룰 때

#### Character Stream 사용
- 텍스트 파일
- 로그 파일
- 사용자 입력
> 문자 의미가 중요할 때

## 4. 표준 스트림 (System.in / System.out / System.err)
운영체제가 기본적으로 제공하는 입출력 통로 <br>
자바에서는 System 클래스가 제공
| 스트림        | 역할    |
| ---------- | ----- |
| System.in  | 입력    |
| System.out | 일반 출력 |
| System.err | 에러 출력 |


### 각 스트림의 정보
#### System.in
- 타입 : `InputStream`
- 입력 : 키보드
```java
int data = System.in.read();
```

#### System.out
- 타입 : `PrintStream`
- 출력 : 에러 로그
```java
System.err.println("Error 발생");
```

#### System.err
- 타입 : `PrintStream`
- 출력 : 콘솔
```java
System.out.println("Hello");
```

#### out 과 err의 차이
| 항목    | System.out | System.err |
| ----- | ---------- | ---------- |
| 용도    | 일반 출력      | 에러 출력      |
| 버퍼    | 있음         | 없음 (즉시 출력) |
| 로그 분리 | 어려움        | 가능         |

### 자주 사용하는 System.out.println의 내부 구조
```
System.out → PrintStream 객체
           → write()
           → OutputStream
           → OS 콘솔 출력
```
- `System.out`은 단순한 스트림이 아니라 PrintStream
- println은 내부적으로 write 호출

### System.in의 실무
직접 사용하는 일이 거의 없음
- 1바이트 단위의 입력이 느리고 불편
- BufferedReader 사용

## 5. 파일 읽고 쓰기 (File I/O)
자바에서 파일 I/O는 파일을 스트림으로 열어서 읽고(write/read) 닫는 과정
```
File → Stream → Buffer → 처리
```

### 파일 읽기
#### Byte 기반
```java
InputStream in = new FileInputStream("test.txt");

int data;
while ((data = in.read()) != -1) {
    System.out.print((char) data);
}
in.close();
```
단점
- 1바이트씩 읽어서 느림

#### Character + Buffer 조합 (실무)
```java
BufferedReader br = new BufferedReader(
    new InputStreamReader(
        new FileInputStream("test.txt"), "UTF-8"
    )
);

String line;
while ((line = br.readLine()) != null) {
    System.out.println(line);
}
```
핵심
- 인코딩 처리
- 라인 단위 처리
- 성능 최적화

### 파일 쓰기
#### 기본 버전
```java
OutputStream out = new FileOutputStream("test.txt");

out.write("Hello".getBytes());
out.close();
```

#### 실무 표준
```java
BufferedWriter bw = new BufferedWriter(
    new OutputStreamWriter(
        new FileOutputStream("test.txt"), "UTF-8"
    )
);

bw.write("Hello");
bw.newLine();
bw.flush();
bw.close();
```

### NIO 방식
Files 사용
```java
List<String> lines = Files.readAllLines(Path.of("test.txt"));

Files.write(Path.of("test.txt"), "Hello".getBytes());
```

### IO VS NIO 비교
| 항목  | IO     | NIO              |
| --- | ------ | ---------------- |
| 방식  | Stream | Channel + Buffer |
| 처리  | 순차     | 병렬/비동기           |
| 성능  | 낮음     | 높음               |
| API | 복잡     | 간결 (Files)       |

### 파일 읽기 방법 선택 기준
- 작은 파일 : `Files.readAllLines()`
- 큰 파일 : `BufferedReader`
- 대용량/고성능 : `FileChannel`
