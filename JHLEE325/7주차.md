## 패키지

## 1. package 키워드

### package 키워드의 개념
- 클래스들을 논리적으로 묶는 네임스페이스
- 물리적으로는 디렉토리 구조와 1:1 매핑

### package의 특징
- 클래스 이름 충돌 방지
- 코드 구조화 (계층적 설계)
- 접근제어자와 결합하여 캡슐화 구현
- 물리적으로 디렉토리 구조와 매핑됨
  ```
  com.example.service → com/example/service
  ```
- FQCN (Fully Qualified Class Name): 클래스의 전체 이름은 `패키지명.클래스명`이다. (예: `java.util.ArrayList`) JVM은 내부적으로 이 FQCN을 통해 클래스를 식별함.
- 계층 구조의 오해: com.example과 com.example.util은 인간이 보기엔 계층 구조지만, 자바 입장에서는 완전히 별개의 패키지임. (상속이나 접근 제어 권한이 자동으로 이어지지 않음)

### package의 기본 규칙
- 소스 파일 최상단에 선언
- 하나의 파일에는 하나의 package 선언만 가능
- package 선언이 없으면 default package에 속함

#### default package?
```java
class Test {}
```
- package 선언이 없는 경우
- 다른 패키지에서 import 불가능
- 실무에서는 사용하지 않음

### package 네이밍 규칙
도메인 역순 + 계층 구조 <br>
예시) com.company.project.module
- 소문자 사용
- 회사 도메인 역순 사용
- 의미 있는 계층 구조를 갖도록

## 2. import 키워드

### import의 개념
다른 패키지의 클래스를 사용할 때 패키지명을 생략하고 사용 가능하게 해주는 문법

### import의 특징
- 컴파일러가 소스 코드의 짧은 이름을 FQCN으로 바꿀 수 있게 도와주는 도구일 뿐, 실제 실행 시(Runtime) 성능에는 아무런 영향이 없음.
- 이름 충돌 시 명시적 경로 사용 필요
  ```java
  java.util.Date d1;
  java.sql.Date d2;
  // 위 처럼 Date 이름이 겹칠 경우 명시적으로 d1, d2 처럼 해줘야함
  ```
- 와일드카드(*)의 범위: `import java.util.*;`을 해도 `java.util.zip` 같은 하위 패키지의 클래스까지 가져오지는 않음.

### import의 기본 사용법
```java
import java.util.List; // java.util.List를 import
import java.util.*; // java.util의 전체를 import
// static import
import static java.lang.Math.*; // java.lang.Math의 전체를 static import
// 이러면 Math.sqrt()를 Math를 안쓰고 바로 sqrt() 로 쓸 수 있음
```

### import를 생략 가능한 경우
- 같은 패키지인 경우
- java.lang 패키지인 경우
  ```java
  String s; // import 하지 않고 바로 String 사용 가능
  ```

## 3. Classpath

### Classpath의 개념
JVM이 프로그램을 실행할 때, 사용자 정의 클래스와 라이브러리(`.jar`)를 찾기 위해 참조하는 탐색 경로의 리스트.

### Classpath를 사용하는 이유
- 외부 라이브러리를 사용하는 경우
- 다른 디렉토리 클래스를 참조하는 경우

### 문제 상황
클래스 패스 오류 발생 시
- ClassNotFoundException
- NoClassDefFoundError
위 오류들 발생

### 특징

## 5. -classpath 옵션

### -classpath의 개념
실행 시 직접 클래스 경로 지정

### 특징
- 실행 단위별 설정 가능
- 가장 권장되는 방식

## 6. 접근지시자 (Access Modifier)

### 접근지시자의 종류
| 접근지시자     | 같은 클래스 | 같은 패키지 | 자식 클래스 | 다른 패키지 |
| --------- | ------ | ------ | ------ | ------ |
| public    | O      | O      | O      | O      |
| protected | O      | O      | O      | X      |
| default   | O      | O      | X      | X      |
| private   | O      | X      | X      | X      |

### 접근지시자의 핵심 포인트
- 캡슐화
- 접근 범위 제한
- API 설계 핵심 요소
