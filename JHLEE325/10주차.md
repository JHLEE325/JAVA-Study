## 멀티쓰레드

## 1. Thread 클래스와 Runnable 인터페이스

### 멀티쓰레드 기본 개념
- 프로세스: 실행 중인 프로그램 (독립된 메모리 공간)
- 쓰레드: 프로세스 내부의 실행 단위 (Stack만 별도, Heap은 공유)
- 하나의 프로세스 안에서 여러 작업을 동시에 수행 -> 멀티쓰레드
- JVM은 쓰레드 기반으로 동작 (GC도 쓰레드임)

### Thread 생성 방법 (2가지)
1. Thread 클래스 상속
   ```java
   class MyThread extends Thread {
      @Override
      public void run() {
          System.out.println("Thread 실행");
      }
    }

    new MyThread().start();
    ```
2. Runnable 인터페이스 구현
    ```java
    class MyRunnable implements Runnable {
        @Override
        public void run() {
            System.out.println("Runnable 실행");
        }
    }

    new Thread(new MyRunnable()).start();
    ```

### Thread vs Runnable 차이
| 구분    | Thread   | Runnable     |
| ----- | -------- | ------------ |
| 방식    | 클래스 상속   | 인터페이스 구현     |
| 상속 제한 | 단일 상속 제한 | 다른 클래스 상속 가능 |
| 역할    | 실행 + 작업  | 작업 정의        |
| 재사용성  | 낮음       | 높음           |
| 실무 사용 | ❌ 거의 안씀  | ✅ 표준         |

핵심 포인트
- Thread는 "실행 도구"
- Runnable은 "작업 정의"

좋은 설계
```java
Runnable task = () -> { ... };
new Thread(task).start();
```

### start() vs run()
```java
thread.start(); // 새로운 쓰레드 생성 → run() 실행
thread.run();   // 그냥 메서드 호출 (싱글 쓰레드)
```

핵심
- `start()`: 새로운 call stack 생성
- `run()`: 기존 main threaad에서 실행

### 왜 Runnable이 더 좋은가?
1. 객체 지향 설계
   - 역할 분리
2. 상속 제약 해결
   - Java는 단일 상속
   - Runnable은 인터페이스라 자유
3. 쓰레드 풀과 호환
   - ExecutorService는 Runnable 기반
     ```java
     ExecutorService pool = Executors.newFixedThreadPool(3);
     pool.submit(() -> System.out.println("작업"));
     ```
     실무에서는 Thread 직접 생성을 거의 하지 않음

#### Callable
Runnable은 반환값 없음 → 한계 존재 <br>
해결: `Callable`
```java
Callable<Integer> task = () -> 1 + 2;

Future<Integer> result = executor.submit(task);
result.get(); // 결과 반환
```

### Thread 내부 구조
Thread가 실행되면:
- 새로운 Stack 생성
- Heap 공유
- PC Register 별도

JVM 관점:
- 각 Thread는 독립 실행 흐름
- 메모리는 공유 → 동기화 필요

### 핵심 정리
- Thread 생성 방식은 2가지 (Thread / Runnable)
- Runnable이 설계적으로 더 우수
- start() vs run() 차이 중요
- 실무에서는 ExecutorService + Runnable/Callable 사용

## 2. 쓰레드의 상태 (Thread State)

### 쓰레드 상태 개요
자바에서 쓰레드는 생성부터 종료까지 6가지 상태를 가짐
```java
public enum Thread.State {
    NEW,
    RUNNABLE,
    BLOCKED,
    WAITING,
    TIMED_WAITING,
    TERMINATED
}
```

### 전체 상태 흐름
```
NEW → RUNNABLE → (RUNNING)
              ↘
      BLOCKED / WAITING / TIMED_WAITING
              ↘
          RUNNABLE → TERMINATED
```
핵심
- RUNNING은 별도 상태가 아니라 RUNNABLE에 포함
- OS 스케줄러가 실행 여부 결정
 
### 상태별 상세 설명
#### NEW (생성 상태)
```java
Thread t = new Thread();
```
- 아직 start()를 호출하기 전
- 쓰레드 객체만 존재
- 실행 불가 상태
- start()를 호출해야 다음 단계로 진행

#### RUNNABLE (실행 가능 상태)
```java
t.start();
```
- 실행 대기/실행 중 상태 포함
- CPU 할당 받으면 실행
- JVM 입장에서는 RUNNING도 포함
- "실행 중" 상태는 따로 없음

#### BLOCKED (락 대기 상태)
```java
synchronized(lock) {
    // 다른 스레드가 이미 점유 중
}
```
- 모니터 락 획득 대기
- synchronized 진입 못하는 상태
- CPU 필요 없음
- 락만 기다림

#### WATING (무한 대기)
```java
object.wait();
thread.join();
LockSupport.park();
```
- 다른 쓰레드의 신호(notify)를 기다리는 상태
- 무기한 대기

#### TIMED_WATING (시간 제한 대기)
```java
Thread.sleep(1000);
object.wait(1000);
thread.join(1000);
```
- 일정 시간 동안 대기
- 시간이 지나면 자동 복귀
WATING과의 차이
- 무한 대기와 시간 제한의 차이

#### TERMINATED (종료 상태)
```java
run() 메서드 종료
```
- 쓰레드 완전히 종료
- 재실행 불가

### 상태 전이 핵심 정리
| 현재 상태         | 이벤트       | 다음 상태         |
| ------------- | --------- | ------------- |
| NEW           | start()   | RUNNABLE      |
| RUNNABLE      | lock 못 얻음 | BLOCKED       |
| RUNNABLE      | wait()    | WAITING       |
| RUNNABLE      | sleep()   | TIMED_WAITING |
| WAITING       | notify()  | RUNNABLE      |
| TIMED_WAITING | 시간 만료     | RUNNABLE      |
| RUNNABLE      | 종료        | TERMINATED    |

### BLOCKED vs WATING
| 구분      | BLOCKED           | WAITING       |
| ------- | ----------------- | ------------- |
| 원인      | synchronized 락 대기 | wait()/join() |
| 깨어나는 조건 | 락 획득              | notify()      |
| 대상      | 락                 | 스레드 신호        |
| CPU 사용  | ❌                 | ❌             |

## 3. 쓰레드의 우선순위 (Thread Priority)

### 우선순위 개념
자바에서 각 쓰레드는 우선순위를 가짐
```java
//Thread
thread.setPriority(int priority);

//범위
Thread.MIN_PRIORITY = 1
Thread.NORM_PRIORITY = 5 (기본값)
Thread.MAX_PRIORITY = 10
```

### 우선순위의 의미
- 우선순위가 높을수록 CPU를 할당받을 “가능성”이 높아짐
- 절대 보장 X

### 동작 방식
자바 쓰레드는 실제로는 OS 스케줄러에 의존
- JVM -> 힌트 제공
- OS -> 실제 스케줄링 진행

결론
- 우선순위가 높아도 실행이 안될 수 있고, 낮아도 실행될 수 있음
- 예시
  ```java
  Thread t1 = new Thread(() -> {
       while (true) System.out.println("LOW");
   });

   Thread t2 = new Thread(() -> {
       while (true) System.out.println("HIGH");
   });

   t1.setPriority(Thread.MIN_PRIORITY);
   t2.setPriority(Thread.MAX_PRIORITY);

   t1.start();
   t2.start();
  ```
  - 위에서 HIGH가 더 많이 실행될 가능성 있지만 항상 그런 것은 아님

### 왜 우선순위를 완전히 신뢰하면 안되는가?
1. OS에 종속되기 때문에 Windows, Linux, macOS 각기 다 다름
2. JVM 구현에 따라 HosSpot, OpenJ9이 다 다름
3. 스케줄링 정책에 따라 다름

결론
- 우선순위는 단순 힌트

### 우선순위 상속 (Inheritance)
```java
Thread parent = Thread.currentThread();
Thread child = new Thread(...);
```
특징
- 자식 쓰레드는 부모 우선순위 상속

### 실무 관점에서의 우선순위
잘 쓰지 않는다. <br>
이유
- 예측 불가능
- 성능 보장 안됨
- 유지보수 힘듬

#### 대체제: ExecutorService + 쓰레드 풀
```java
ExecutorService executor = Executors.newFixedThreadPool(3);
```
- 스레드 개수 제어
- 안정적인 성능

#### 대체제: 작업 큐 기반 제어
```java
ExecutorService executor = Executors.newFixedThreadPool(3);
```
- 우선순위는 쓰레드가 아니라 작업에 부여

## 4. Main 쓰레드 (Main Thread)

### Main Thread란?
프로그램 실행 시 가장 먼저 생성되는 스레드
```java
public static void main(String[] args)
```
`main` 메서드를 실행하는 주체가 Main Thread

### 실행 흐름 (JVM 관점)
1. JVM 시작
2. 클래스 로딩
3. main() 메서드 호출
4. Main Thread 생성 및 실행
즉, 프로그램 시작 = Main Thread 시작

### 특징
1. 모든 쓰레드의 시작점
   ```java
   public static void main(String[] args) {
      new Thread(() -> System.out.println("child")).start();
   }
   ```
   - 자식 쓰레드는 Main Thread에서 생성됨
2. 일반 쓰레드와 동일
   - 특별한 기능이 따로 있는 것이 아니고 그냥 하나의 Thread
   - 단지 처음 생성된 쓰레드
3. 종료 조건
   - 프로그램 종료 조건: 모든 "non-daemon thread" 종료 시 프로그램 종료
   - Main Thread가 끝나도 프로그램이 끝나지 않을 수 있음

### Main Thread 종료 vs 프로그램 종료
#### Main Thread 종료 → 프로그램 종료 X
```java
public static void main(String[] args) {
    new Thread(() -> {
        while (true) {}
    }).start();
}
```
- main은 끝났지만 프로그램은 계속 실행됨

#### 모든 스레드 종료 → 프로그램 종료
- JVM은 살아있는 쓰레드가 있으면 계속 실행함

### Daemon Thread와 관계
```java
Thread t = new Thread(...);
t.setDaemon(true);
```
- 백그라운드 작업용 (GC, 로그 등)
- 위는 daemon thread이기 때문에 종료 조건에 들어있지 않아서 종료에 영향 X

### Main Thread의 문제점
1. 블로킹 문제: main이 멈추면 프로그램 전체 시작이 지연됨
2. 예외 발생 시 종료: main이 죽으면 프로그램이 바로 종료됨
3. 긴 작업 수행: main에서 긴 작업을 직접 처리하지 않고 별도 쓰레드 또는 쓰레드 풀 사용해야 함

## 5. 동기화 (Synchronization)

### 동기화란?
- 여러 스레드가 공유 자원에 동시에 접근할 때
- 데이터 일관성을 보장하는 것

### 문제 상황 (Race Condition)
```java
class Counter {
    int count = 0;

    void increment() {
        count++; // 문제 발생
    }
}
```
`count++`는 3단계
```
1. 읽기 (read)
2. 계산 (modify)
3. 쓰기 (write)
```
- 두개 이상의 쓰레드에서 동시에 실행하면 값 덮어쓰기가 발생함

### 임계 영역 (Critical Section)
위에서 나온 `count++`처럼 동시에 하나의 쓰레드만 접근해야 하는 코드 영역을 보호 하는 것이 동기화

### 기본적인 동작
1. 메서드 동기화
2. 블록 동기화
```java
synchronized void increment() {
    count++;
}
// 객체의 모니터 락을 획득

void increment() {
    synchronized(this) {
        count++;
    }
}
// 필요한 부분만 락 걸어서 성능 개선
```

### 동기화 동작 원리
핵심: 모니터 락(Monitor Lock)
- 객체마다 락 존재
- 한 번에 하나의 쓰레드만 획득
  ```
  Thread A → lock 획득 → 실행
  Thread B → BLOCKED 상태 대기
  ```

### Synchronized 특징
1. 상호 배제: 한 번에 하나만 실행
2. 가시성 보장: 변경된 값을 다른 쓰레드에 즉시 반영 - 메모리 flush/reload 발생 때문
3. 원자성 보장: 중간 끼어들기 방지

### Synchronized의 문제점
1. 성능 저하: 락 경쟁 발생
2. BLOCKED 상태 증가: 병목 발생
3. 데드락 위험: 잘못 쓰면 무한 대기 상태에 교착됨

### volatile
자바의 키워드로, 멀티쓰레드 환경에서 변수의 가시성과 일관성을 보장하기 위해 사용
- 목적: 변수의 메모리 가시성 보장
- 적용 대상: 인스턴스 및 클래스 변수
- 쓰레드 안전성: 원자성은 보장X
사용 예시
```java
while (!flag) {
    // busy waiting
}
// 다른 쓰레드가 flag 변경 시 바로 반영
```

### Synchronized vs volatile
| 구분  | synchronized | volatile |
| --- | ------------ | -------- |
| 원자성 | ⭕            | ❌        |
| 가시성 | ⭕            | ⭕        |
| 락   | 사용           | 없음       |
| 성능  | 느림           | 빠름       |

### Lock 인터페이스
```java
Lock lock = new ReentrantLock();

lock.lock();
try {
    count++;
} finally {
    lock.unlock();
}
```
- tryLock()가능
- 공정성 설정 가능
- 인터럽트 처리 가능

### AtomicInteger
하나의 `int`값을 원자적으로 업데이트할 수 있도록 설계된 동시성 유틸리티 <br>
동기화 블록 없이 쓰레드 안전한 정수 연산 수행 가능
```java
AtomicInteger count = new AtomicInteger(0);
count.incrementAndGet();
```
- 락 없이 동기화
- CAS(Compare-And-Swap) 사용

## 6. 데드락 (Deadlock)

### 데드락이란?
두 개 이상의 쓰레드가 서로가 가진 자원을 기다리며 영원히 멈추는 상태

### 대표 예시
```java
Object lock1 = new Object();
Object lock2 = new Object();

Thread t1 = new Thread(() -> {
    synchronized(lock1) {
        synchronized(lock2) {
            System.out.println("t1 작업");
        }
    }
});

Thread t2 = new Thread(() -> {
    synchronized(lock2) {
        synchronized(lock1) {
            System.out.println("t2 작업");
        }
    }
});

// t1: lock1 획득 → lock2 대기
// t2: lock2 획득 → lock1 대기
```
서로 기다리다가 영원히 멈춤

### 데드락 발생 조건
1. 상호 배제: 자원은 한 번에 하나만 사용
2. 점유 대기: 하나가 가진 상태에서 다른 것 기다림
3. 비선점: 강제로 뺏을 수 없음
4. 순환 대기: 서로 물고 물리는 구조

### 데드락 해결 방법
1. 락 순서 통일
2. tryLock 사용: 일정 시간 이후 포기
3. 타임아웃 설정
4. 락 최소화: synchronized 범위 줄이기
