## 람다식(Lambda Expression)

## 1. 람다식이란?

### 람다식의 기본 개념
람다식은 메서드를 하나의 식처럼 표현하는 문법 <br>
익명 함수를 간결하게 표현 하기 위한 기능으로 Java 8에서 도입됨

### 람다식 등장 배경
#### 람다식 이전
```java
Runnable r = new Runnable() {
    @Override
    public void run() {
        System.out.println("Hello");
    }
};
```
문제점
- 코드가 장황함
- 의도 파악이 안됨
- 함수 자체보다 문법이 더 많음

#### 람다식 사용
```java
Runnable r = () -> System.out.println("Hello");
```
핵심
- 불필요한 boilerplate 제거
- 함수 자체에 집중 가능

### 람다식 기본 문법
```java
(파라미터) -> { 실행문 }

// 매개변수 없는 경우
() -> System.out.println("Hello")

// 매개변수 1개
x -> x * x

// 매개변수 여러개
(a, b) -> a + b

// 실행문 여러줄
(a, b) -> {
    int result = a + b;
    return result;
}
```

### 람다식의 본질
람다식은 메서드가 아니다 <br>
자바에서 람다는 함수영 인터페이스 객체
```java
Runnable r = () -> System.out.println("Hello");
```
컴파일러 관점에서 위는 Runnable 구현 객체 생성과 거의 동일

### 함수영 인터페이스와 연결
람다식은 반드시 추상 메서드가 1개인 인터페이스에만 사용 가능
| 인터페이스      | 메서드       |
| ---------- | --------- |
| Runnable   | run()     |
| Comparator | compare() |
| Callable   | call()    |

### 타입 추론
람다식은 문맥(Context) 기반으로 타입 추론
```java
Comparator<String> c =
    (a, b) -> a.compareTo(b);
```
여기서
- a, b가 타입을 명시하지 않아도
- 컴파일러가 String으로 추론

### 람다식 vs 익명 클래스
| 항목   | 람다식   | 익명 클래스   |
| ---- | ----- | -------- |
| this | 바깥 객체 | 익명 객체 자신 |
| 목적   | 함수 전달 | 객체 생성    |
| 코드량  | 적음    | 많음       |
| 의미   | 함수적   | 객체지향적    |

### this의 차이
#### 익명 클래스
```java
new Runnable() {
    @Override
    public void run() {
        System.out.println(this);
    }
}
```
this = 익명 객체 자신

#### 람다식
```java
() -> {
    System.out.println(this);
}
```
this = 바깥 클래스 객체

### 람다식의 장점
- 코드 간결화
- 함수 전달 가능
- Stream API와 결합

### 람다식의 단점
- 디버깅 어려움
- 남용 시 가독성 저하
- 상태 공유 시 복잡성 증가

### 람다 내부 동작
람다는 익명클래스처럼 `.class`파일을 생성하지 않음

### 주요 포인트
| 주제                | 핵심                                |
| ----------------- | --------------------------------- |
| Lambda Expression | 메서드를 식(Expression)처럼 표현           |
| 등장 배경             | 익명 클래스 boilerplate 제거             |
| 목적                | 함수형 프로그래밍 스타일 지원                  |
| 기본 문법             | `(param) -> {}`                   |
| 본질                | 함수형 인터페이스 구현 객체                   |
| 특징                | 코드 간결화 + 함수 전달 가능                 |
| 타입 추론             | 컴파일러가 문맥 기반 추론                    |
| 사용 조건             | 함수형 인터페이스 필요                      |
| 내부 동작             | invokedynamic + LambdaMetafactory |
| 익명 클래스 차이         | this 바인딩 방식 다름                    |
| 장점                | 가독성, 선언형 프로그래밍                    |
| 단점                | 디버깅 어려움, 남용 시 가독성 저하              |
| Stream API        | filter/map/forEach와 자주 사용         |
| 함수형 프로그래밍         | 상태 공유 최소화 지향                      |
| 핵심 철학             | 동작(Behavior)을 값처럼 전달              |

## 2. 함수형 인터페이스

### 함수형 인터페이스의 기본 개념
함수형 인터페이스란 추상 메서드가 딱 1개만 존재하는 인터페이스 <br>
람다식은 하나의 메서드를 구현하는 것이기 때문에 대상 인터페이스도 메서드 하나만 가져야 함

### 예시
```java
@FunctionalInterface
interface Calculator {
    int calc(int a, int b);
}

// 람다식 변환
Calculator add = (a, b) -> a + b;
```

### 추상 메서드가 1개여야 하는 이유
람다식은 어떤 메서드를 구현하는 것인지 명확하여야 함

```java
interface A {
    void x();
    void y();
}

() -> {}
```
위처럼 되어 있으면
- x 구현인지 y 구현인지 알 수가 없음

### @FunctionalInterface
컴파일러에게 이 인터페이스는 함수형 인터페이스여야 한다 라고 명시하는 것
```java
@FunctionalInterface
interface MyFunction {
    void run();
}

@FunctionalInterface
interface MyFunction {
    void run();
    void test(); // 컴파일 에러
}
```
함수형 인터페이스가 아닐 때의 실수를 방지

### default / static 메서드
함수형 인터페이스는 추상 메서드만 1개 이면 되기 때문에 default, static 메서드는 가질 수 있음
```java
@FunctionalInterface
interface MyFunction {

    void run();

    default void print() {}

    static void hello() {}
}
```

### Object 메서드
```java
@FunctionalInterface
interface MyFunction {

    void run();

    String toString();
}
```
Object 메서드도 추상 메서드 개수에서 제외

### 대표적인 함수형 인터페이스
Java 8의 `java.util.function`

#### Predicate<T>
```java
boolean test(T t)

// 조건 검사
Predicate<Integer> p = x -> x > 10;
```

#### Function<T,R>
```java
R apply(T t)

// 변환 함수
Function<String, Integer> f = s -> s.length();
```

#### Consumer<T>
```java
void accept(T t)

// 소비(출력 등)
Consumer<String> c = s -> System.out.println(s);
```

#### Supplier<T>
```java
T get()

// 값 공급
Supplier<Double> s = () -> Math.random();
```

#### Runnable도 함수형 인터페이스
```java
public interface Runnable {
    void run();
}

Runnable r = () -> System.out.println("run");
```

### 함수형 인터페이스의 장점
- 람다식 사용 가능
- Stream API와 결합 가능
- 선언형 프로그래밍 가능

### 실무 활용 분야
| 분야         | 사용         |
| ---------- | ---------- |
| Stream API | filter/map |
| Comparator | 정렬         |
| Thread     | Runnable   |
| Spring     | callback   |
| 이벤트 처리     | listener   |

### 주요 포인트
| 주제                   | 핵심                                         |
| -------------------- | ------------------------------------------ |
| Functional Interface | 추상 메서드가 1개인 인터페이스                          |
| 목적                   | 람다식 대상 타입 제공                               |
| 핵심 조건                | 추상 메서드 정확히 1개                              |
| @FunctionalInterface | 컴파일 타임 검증                                  |
| default/static 메서드   | 여러 개 가능                                    |
| Object 메서드           | 추상 메서드 개수 계산 제외                            |
| 본질                   | 함수를 객체처럼 다루기 위한 구조                         |
| 람다와 관계               | 람다는 함수형 인터페이스 구현 객체                        |
| 대표 인터페이스             | Predicate / Function / Consumer / Supplier |
| Predicate            | 조건 검사                                      |
| Function             | 입력 → 변환                                    |
| Consumer             | 소비(반환 없음)                                  |
| Supplier             | 값 공급                                       |
| Runnable             | 대표적인 함수형 인터페이스                             |
| Stream API           | 함수형 인터페이스 기반                               |
| 핵심 철학                | 함수(Function)를 객체(Object)처럼 사용              |

## 3. 변수 캡쳐 (Variable Capture)

### 변수 캡쳐란?
람다식 내부에서 바깥 변수를 참조하는 것이 변수 캡쳐
```java
int x = 10;

Runnable r = () -> {
    System.out.println(x);
};
```
람다가자기 내부 변수, 파라미터가 아닌 외부 x를 사용함

### 캡쳐라고 부르는 이유
람다는 실행 시점에 외부 변수 값을 복사해서 보관하기 때문 <br>
외부 변수 자체를 들고 있는 것이 아님

### 제약사항
람다에서 사용하는 지역변수는 final 또는 effectively final

```java
// 가능
int x = 10;

Runnable r = () -> System.out.println(x);

// 불가능
int x = 10;

Runnable r = () -> System.out.println(x);

x++; // 컴파일 에러
```
effectively final : 명시적 final은 아니나 값이 한 번만 할당된 상태

#### 제약이 필요한 이유
지역 변수는 Stack에 존재하는데 람다는 Stack보다 오래 남아있을 수 있기 때문
```java
Runnable getRunnable() {

    int x = 10;

    return () -> System.out.println(x);
}
```
메서드 종료 후 x는 stack에서 제거되나 람다는 살아있을 수 있음 <br>
그래서 JVM은 값을 복사해서 람다 내부에 저장하여 사용

#### 변경 금지인 이유
```java
int x = 10;

Runnable r = () -> System.out.println(x);

x = 20;
```
람다가 10을 봐야하는지 20을 봐야하는지 불명확 <br>
또한 멀티스레드 환경에서 동기화 문제 발생 가능

### 인스턴스 변수와 static 변수
#### 인스턴스 변수
```java
class A {

    int x = 10;

    void foo() {
        Runnable r = () -> System.out.println(x);
        x++;
    }
}
```
인스턴스 변수는 stack이 아니라 heap에 존재하여 객체 생명주기와 동일 <br>
복사가 필요없고 참조 가능

#### static 변수
```java
static int x = 10;
```
static 변수도 heap/method Area 기반

### 주요 포인트
| 주제                | 핵심                           |
| ----------------- | ---------------------------- |
| Variable Capture  | 람다가 외부 변수 사용하는 것             |
| Capture 방식        | 변수 참조가 아니라 값 복사              |
| 지역 변수 제약          | final 또는 effectively final   |
| effectively final | 한 번만 할당된 상태                  |
| 제약 이유             | 지역 변수는 Stack 메모리             |
| 람다 생명주기           | 메서드 종료 이후에도 살아남을 수 있음        |
| JVM 처리 방식         | 캡처 값을 람다 내부에 저장              |
| 값 변경 제한 이유        | 일관성 문제 + 동기화 문제 방지           |
| 인스턴스 변수           | 변경 가능                        |
| static 변수         | 변경 가능                        |
| 이유                | Heap 기반이라 생명주기 보장            |
| 익명 클래스            | 동일하게 effectively final 제약 존재 |
| 함수형 철학            | 불변성(Immutability) 지향         |
| 멀티스레드 관점          | 상태 공유 최소화                    |
| 핵심 철학             | 람다는 지역 변수를 직접 참조하지 않음        |

## 4. 메서드 레퍼런스(Method Reference) / 생성자 레퍼런스(Constructor Reference)

### 메서드 레퍼런스란?
메서드 레퍼런스는 람다식을 더 간결하게 표현하는 문법 <br>
람다식이 단순히 메서드 호출만 하는 경우 메서드 이름 자체를 전달 가능

### 메서드 레퍼런스 기본 문법
```java
클래스명::메서드명
객체명::메서드명
```
예시
```java
x -> System.out.println(x)

System.out::println
```

### 사용 이유
- 코드 간결화
- 의도 명확화
- 함수 전달 느낌 강화

### 메서드 레퍼런스 종류
| 종류             | 예시                    |
| -------------- | --------------------- |
| static 메서드     | Class::staticMethod   |
| 특정 객체 인스턴스 메서드 | obj::instanceMethod   |
| 임의 객체 인스턴스 메서드 | Class::instanceMethod |
| 생성자 레퍼런스       | Class::new            |

### static 메서드 레퍼런스
```java
Function<String, Integer> f = Integer::parseInt;

// 람다식
s -> Integer.parseInt(s)
```

### 특정 객체의 인스턴스 메서드 레퍼런스
```java
String str = "Hello";

Supplier<String> s = str::toUpperCase;

// 람다식
() -> str.toUpperCase()
```

### 임의 객체의 인스턴스 메서드 레퍼런스
```java
Comparator<String> c = String::compareToIgnoreCase;

// 람다식
(a, b) -> a.compareToIgnoreCase(b)
```
첫번째 파라미터가 메서드 호출 대상

### 생성자 레퍼런스란?
생성자를 함수처럼 참조하는 문법 <br>
객체 생성 로직을 람다식 대신 전달할 수 있게 함

### 생성자 레퍼런스 사용 이유
람다식에서 객체 생성만 수행하는 경우가 매우 많기 때문
```java
name -> new Person(name)
```
로직 없이 단순 생성자 호출만 수행하는 경우

### 생성자 레퍼런스 기본 문법
```java
클래스명::new
```
예시
```java
Supplier<List<String>> s = ArrayList::new;

// 람다식
() -> new ArrayList<>()

Function<String, Person> f = Person::new;

// 람다식
name -> new Person(name)
```

### 주요 포인트
| 주제                    | 핵심                             |
| --------------------- | ------------------------------ |
| Method Reference      | 기존 메서드를 함수처럼 참조                |
| Constructor Reference | 생성자를 함수처럼 참조                   |
| 본질                    | 람다식 축약 문법(Syntactic Sugar)     |
| 목적                    | 코드 간결화 + 선언형 표현                |
| 사용 조건                 | 단순 메서드/생성자 호출만 가능              |
| 표현 방식                 | `Class::method`, `Class::new`  |
| 내부 동작                 | invokedynamic 기반               |
| 함수형 인터페이스             | 대상 추상 메서드와 매핑                  |
| 장점                    | 가독성 향상, 의도 명확                  |
| 람다와 차이                | 람다 = 동작 정의 / 레퍼런스 = 기존 동작 참조   |
| static 메서드 레퍼런스       | `Integer::parseInt`            |
| 인스턴스 메서드 레퍼런스         | `System.out::println`          |
| 임의 객체 메서드 레퍼런스        | `String::compareToIgnoreCase`  |
| 생성자 레퍼런스              | `Person::new`                  |
| 실무 사용처                | Stream API, Comparator, 컬렉션 변환 |
| 제한 사항                 | 복잡한 로직은 일반 람다 사용               |
| 핵심 철학                 | “어떻게”보다 “무엇을” 표현               |
